# Sam Smith School of Dance — Thanksgiving Squares

Working deployable prototype. Not publicly deployed. Price: $20/square. Opponent: Kansas City Chiefs (provided by organizer). Game year, payment recipient, contact, and prizes await organizer confirmation.

## Local preview
Requires Python 3.9 or newer; no packages to install.

    python3 server.py

Open http://127.0.0.1:8000. The terminal prints a temporary organizer key unless ADMIN_TOKEN is set. Click Organizer and enter the key. Keep it private. For a stable key set ADMIN_TOKEN in your environment. The board refreshes every three seconds. All visitors to the same server use the same SQLite database. Data is saved in data/board.db by default.

## Organizer workflow
Set contact, exact game/opponent, payment instructions, Venmo username (without @), and payout rules in Organizer. Price becomes locked after the first reservation. Supporters select multiple squares and supply both required names. Reservations remain pending until payment is reviewed. Mark paid, mark unpaid, or cancel and release squares. Dancer totals show pledged and collected amounts; payment status is organizer-only. Supporter names are public on the board; dancer names are organizer-only except in the supporter's payment note.

Close sales, resolve every pending reservation, then draw score digits. Both axes receive separate shuffled digits 0–9. Drawing is permanent, prevents reopening and releasing squares, and leaves unsold squares unassigned. Agree on what happens for an unsold winning square before sales. No automated scoring, payouts, expiration, or payment verification is implemented.

Venmo link includes recipient, amount, and a note with supporter, dancer, square numbers, and reservation reference. Treat prefilling as best effort until tested with the actual recipient on iPhone and Android. A visible note is provided for copying. Links do not send money or confirm payment. No recipient is configured yet. Confirm Venmo permits this activity and verify applicable fundraising/game rules before accepting funds.

## Deployment and a shareable link
Use a container host that provides HTTPS and a persistent disk. Build the included Dockerfile, attach the persistent disk at /data, and set these runtime environment values:

- ADMIN_TOKEN: a strong secret generated by the host's secret manager.
- DATABASE_PATH: /data/board.db.
- PORT: the listening port configured on your host (default 8000).

Run ONE service instance with one worker and the persistent disk attached. This SQLite design is not intended for multiple replicas or ephemeral/serverless disks. Keep database backups and test restoring them. The container listens on 0.0.0.0. Configure the host's HTTPS proxy to route its public URL to PORT. The host-generated HTTPS URL becomes the shareable link after deployment succeeds. A domain is optional. Static-only hosting cannot run this shared board.

For broader production use, replace Python's basic HTTP server with a production application server, add organizer sign-in, rate limits and bot protection, audit history, monitoring, and backups. The current organizer interface uses a shared secret in memory and HTTPS is essential. There is no password recovery or organizer account system. Never put the organizer key in a public URL or commit it to source control.

## Verification
Run `python3 test_app.py`. Tests cover competing reservations, required names, organizer authorization, public/private data separation, pending-payment guardrails, digit permutations, and irreversible drawing locks. Browser layout QA is separate.

## Multiple boards
The board picker switches between boards at the same URL. In Organizer, Add next board becomes available after the latest board has 100 reserved squares. Pending reservations count toward capacity; payments are still checked separately. Each board has independent sales status and score digits. Select a board before closing sales, drawing numbers, or managing its reservations. Dancer totals show both all-board totals and selected-board totals. Venmo notes identify the board. Existing single-board records are automatically migrated to Board 1. New boards inherit shared studio, game, price, payment instructions, and rules. Each board has a separate prize pool; announce partial-board rules before sales.

## Excel totals export
In Organizer, click Export dancer totals to Excel. The authenticated download contains All boards and By board tabs with dancer, square count, pledged USD, collected USD, and outstanding USD. Cancelled reservations are excluded. Collected means marked paid by the organizer; the export does not verify external payments. Amounts are gross sales, not net fundraiser allocation.

## Cancel an incomplete board
Select a board, unlock Organizer, and choose Cancel selected board. Confirmation is required. Cancellation closes sales permanently, preserves all reservations/payment records, and excludes the board from active dancer totals. A full board or a board with drawn digits cannot be cancelled. Refund paid supporters separately, then use Record refund completed (or undo the record if entered incorrectly). This records bookkeeping only. Excel includes cancelled board labels in By board and a Refund tracking tab; All boards includes active boards only. Another board may be created after the latest board is cancelled.

## Supporter contact details
Registration includes optional phone and email fields. They are validated when supplied, saved per reservation, and visible only in the organizer reservation table. Existing reservations keep blank contact details. Contact details are excluded from the public board, Venmo notes, and dancer-total exports.

## Reset entire fundraiser
Organizer has a Reset entire fundraiser button on the right of the Lock dashboard row. Two confirmations are required. Reset saves a SQLite backup in data/backups, clears reservations, payment/refund records, score digits and extra boards, and starts one empty Board 1 with sales open. It preserves studio/game/payment/prize settings and the organizer key. It does not send refunds. Backups require server-side restoration; there is no dashboard undo.
